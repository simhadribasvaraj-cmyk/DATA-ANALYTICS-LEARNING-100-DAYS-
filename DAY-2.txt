SQL Identifiers
----------------

SQL identifiers are names used to identify database objects such as.
Database names, Table names, Column names, view names, index names, constraints, triggers, stored procedures.

While we are declaring an identifier we have to follow some rules and regulations.

1. the only allowed characters to declare identifiers a-z or A-Z or 0-9,_,$
2. must begin with a letter or underscore(_).
3. we can't declare identifiers with reserved keywords.
4. spaces are not considered to declare identifiers.
5. identifiers are case sensitive
6. max length to declare identifiers are 15 characters.

SQL Commands
==================
SQL (Structured Query Language) commands are broadly classified into five main categories based on their functionality: DDL, DML, DQL, DCL, and TCL. Each category and every command within it is explained below with its purpose and usage.
Command
Description / Definition
DDL
Data Definition Language - defines and modifies the structure of database objects (tables, schemas, indexes).
DML
Data Manipulation Language - manages data stored within database objects (insert, update, delete).
DQL
Data Query Language - used to fetch/retrieve data from the database.
DCL
Data Control Language - manages permissions and access control on database objects.
TCL
Transaction Control Language - manages transactions to maintain data integrity.


 
1. DDL - Data Definition Language
DDL commands are used to define, create, alter, and remove the structure of database objects such as tables, schemas, and indexes. Changes made by DDL commands are auto-committed and permanent.
Command
Description / Definition
CREATE
Creates a new database object such as a table, database, view, index, or schema. Example: CREATE TABLE Students (ID INT, Name VARCHAR(50));
ALTER
Modifies the structure of an existing database object, such as adding, deleting, or modifying columns in a table. Example: ALTER TABLE Students ADD Email VARCHAR(100);
DROP
Permanently deletes an existing database object (table, database, index, view) along with all its data and structure. This action cannot be rolled back in most databases.
TRUNCATE
Removes all rows/records from a table quickly while keeping the table structure intact for future use. Faster than DELETE as it does not log individual row deletions.
RENAME
Renames an existing database object, such as a table or column, to a new name without changing its structure or data.
COMMENT
Adds explanatory notes or comments to database objects (tables, columns) for documentation purposes; does not affect data or structure.

String and Binary Data Types
Common String Data Types
•   CHAR
•   VARCHAR
•   TEXT
•   TINY TEXT
•   MEDIUM TEXT
•   LONG TEXT
•   ENUM
•   SET
CHAR
•   Fixed-length string data type.
•   Ideal for storing strings that have a consistent length.
•   Pads the string with spaces to the specified length if the input is shorter.
 
  CREATE TABLE example (
      code CHAR(5)
  );
  INSERT INTO example (code) VALUES ('AB'), ('ABCDE');
  -- Output: 'AB   ', 'ABCDE' (padded to 5 characters if shorter)
 
VARCHAR
•   Variable-length string data type.
•   More storage-efficient than CHAR for variable-length strings as it only uses as much space as needed.
•   Maximum length is 65,535 bytes, but keep in mind that UTF-8 characters may take up more than 1 byte each.
 
  CREATE TABLE example (
      name VARCHAR(50)
  );
  INSERT INTO example (name) VALUES ('Alice'), ('Bob');
  -- Output: 'Alice', 'Bob'
 
BINARY
•   Fixed-length binary string.
•   Always stores exactly n bytes.
•   If the data is shorter than n, it is padded with \0 (null bytes).
•   Similar to CHAR(n), but for binary data.
 
  CREATE TABLE test_binary (
      bin_col BINARY(5)
  );
   
  INSERT INTO test_binary (bin_col) VALUES ('abc');
  -- Stored as: 'abc\0\0'
 
VARBINARY
•   Variable-length binary string.
•   Stores up to n bytes.
•   Does not pad data; just stores it as-is.
 
  CREATE TABLE test_varbinary (
      varbin_col VARBINARY(5)
  );
   
  INSERT INTO test_varbinary (varbin_col) VALUES ('abc');
  -- Stored as: 'abc'

TEXT Types, ENUM and SET
Common String Data Types
•   CHAR
•   VARCHAR
•   TEXT
•   TINY TEXT
•   MEDIUM TEXT
•   LONG TEXT
•   ENUM
•   SET
TEXT
•   Used for larger blocks of text, ideal for storing paragraphs or longer descriptions.
•   Can store up to 65,535 characters.
•   Cannot have a default value and is stored outside the table row, which may impact performance for frequently queried columns.
 
  CREATE TABLE example (
      description TEXT
  );
  INSERT INTO example (description) VALUES ('This is a long description text.');
  -- Output: The full text is stored as-is.
 
TINYTEXT, MEDIUMTEXT, LONGTEXT
•   These are variants of the TEXT data type with different maximum storage capacities:
◦    TINYTEXT: up to 255 characters.
◦    MEDIUMTEXT: up to 16,777,215 characters.
◦    LONGTEXT: up to 4,294,967,295 characters.
 
  CREATE TABLE example (
      short_text TINYTEXT,
      medium_text MEDIUMTEXT,
      long_text LONGTEXT
  );
  INSERT INTO example (short_text, medium_text, long_text)
  VALUES ('Short text', 'This is a medium length text.', 'This is a very long text that can hold massive content.');
 
ENUM
•   Used for a predefined list of values.
•   Stores only one value chosen from the list.
•   Saves space as it internally maps each value to an integer.
 
  CREATE TABLE example (
      status ENUM('active', 'inactive', 'pending')
  );
  INSERT INTO example (status) VALUES ('active'), ('inactive');
  -- Output: The status field accepts only one of the specified values.
 
SET
•   Used for a predefined list of values where multiple values can be stored.
•   Each value is stored as a bit in a set of bits, allowing for efficient storage.
 
  CREATE TABLE example (
      permissions SET('read', 'write', 'execute')
  );
  INSERT INTO example (permissions) VALUES ('read,write'), ('write,execute');
  -- Output: The permissions field can store multiple values from the set.
 

 
Date and Time
DATE
•   In SQL, DATE is a data type that stores the date. It does not store time information.
•   The format of the date is, 'YYYY-MM-DD'. For instance, '2022-01-01'.
•   SQL provides several functions to handle and manipulate dates.
Create a table with DATE data type
•   In this example, the OrderDate column uses the DATE data type to store the date of the order.
 
  CREATE TABLE Orders (
      OrderId int,
      ProductName varchar(255),
      OrderDate date
  );
 
Insert a date value into a table
•   This command inserts a new row into the Orders table with a date.
 
  INSERT INTO Orders (OrderId, ProductName, OrderDate)
  VALUES (1, 'Product 1', '2022-01-01');
 
Retrieve data with a specific date
•   This command retrieves all orders made on January 1, 2022.
 
  SELECT * FROM Orders
  WHERE OrderDate = '2022-01-01';
 
Date Functions
•   In SQL, the DateTime data type is used to work with dates and times.
•   SQL Server comes with numerous functions for processing dates and times.
•   Some of these include:
◦    CURDATE()
◦    DATE_ADD()
◦    DATE_SUB()
◦    DATEDIFF()
CURRENT_DATE()
•   Returns the current date.
 
  SELECT CURDATE();
 
DATEADD() & DATESUB()
•   Add or subtract a specified time interval from a date.
 
  SELECT DATE_ADD('2024-01-09', INTERVAL 3 MONTHS)
  SELECT DATE_SUB('2024-01-09', INTERVAL 3 MONTHS)
 
DATEDIFF()
•   Get the difference between two dates.
 
  SELECT DATEDIFF('2024-01-09', '2024-01-14')
 
TIME
•   In SQL, TIME data type is used to store time values in the database.
•   It allows you to store hours, minutes, and seconds.
•   The format of a TIME is 'HH:MI:SS'.
Syntax
 
  CREATE TABLE table_name (
      column_name TIME
  );
 
Inserting Data
•   This command inserts a new row into the Orders table with a TIME.
Syntax
 
  INSERT INTO table_name (column_name) values ('17:34:20');
 
Time Functions
•   SQL provides several functions to work with the TIME data type. Some of them include:
◦    CURTIME()
◦    ADDTIME()
◦    SUBTIME()
CURTIME()
•   Returns the current Time
 
  SELECT CURTIME();
 
ADDTIME() & SUBTIME()
•   Add and Subtract time values
 
  SELECT ADDTIME('11:30:45', '15:30:45')
  SELECT SUBTIME('11:30:45', '15:30:45')
 
TIMESTAMP
•   SQL TIMESTAMP is a data type that allows you to store both date and time.
•   It is typically used to track updates and changes made to a record, providing a chronological time of happenings.
•   The format is as follows: 'YYYY-MM-DD HH:MI:SS'
Creating Table
Basic TIMESTAMP column:
 
  CREATE TABLE table_name (
      column1 TIMESTAMP,
      column2 VARCHAR(100),
      ...
  );
 
With a default value of the current timestamp:
 
  CREATE TABLE table_name (
      column1 TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
      column2 VARCHAR(100),
      ...
  );
 
UPDATE CURRENT_TIMESTAMP
•   In MySQL, ON UPDATE CURRENT_TIMESTAMP can be used to automatically update the TIMESTAMP field to the current date and time whenever there is any change in other fields of the row.
 
  CREATE TABLE table_name (
      column1 TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
      column2 VARCHAR(100),
      ...
  );

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Drop,delete,truncate


Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Drop,delete,truncate


Delete
========
Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.

DML - Data Manipulation Language
DML commands are used to insert, update, delete, and manage data stored inside existing database tables. Unlike DDL, DML changes can typically be rolled back if not committed.
Command
Description / Definition
INSERT
Adds new rows/records of data into a table. Example: INSERT INTO Students (ID, Name) VALUES (1, 'Ravi');
UPDATE
Modifies existing records in a table by changing the values of one or more columns based on a specified condition. Example: UPDATE Students SET Name='Kumar' WHERE ID=1;
DELETE
Removes one or more existing rows from a table based on a specified condition, while keeping the table structure. Can be rolled back if used within a transaction.

Step-by-Step Example in MySQL:
Step 1: Create the Table and Insert Data
First, create the employees table and insert sample data.
-- Drop table if it already exists
DROP TABLE IF EXISTS employees;

-- Create employees table with AUTO_INCREMENT primary key
CREATE TABLE employees (
    employee_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    department VARCHAR(50),
    salary DECIMAL(10, 2)
);

INSERT INTO employees (first_name, last_name, department, salary)
VALUES
('Ravi', 'Kumar', 'HR', 50000.00),
('Anjali', 'Sharma', 'Sales', 60000.00),
('Amit', 'Patel', 'HR', 55000.00),
('Sneha', 'Reddy', 'Engineering', 70000.00),
('Vikram', 'Nair', 'Sales', 65000.00);



Step 2: Use DELETE with Rollback
The DELETE command can be used with a transaction, and changes can be rolled back if needed.
-- Start a transaction
START TRANSACTION;

-- Perform DELETE operation (delete employees from the Sales department)
DELETE FROM employees WHERE department = 'Sales';

-- Check the current state of the table (after DELETE but before commit or rollback)
SELECT * FROM employees;

-- Rollback the transaction (undo the DELETE)
ROLLBACK;

-- Check the data again (after rollback)
SELECT * FROM employees;

Expected Outcome: After ROLLBACK, no rows should be deleted from the table, and the Sales department employees will be restored.
If you had used COMMIT instead of ROLLBACK, the changes would be permanent.
-- COMMIT the changes if you want the DELETE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The employees from the Sales department would be deleted permanently.

Step 3: Use TRUNCATE (Not Rollbackable in MySQL)
In MySQL, TRUNCATE is a DDL (Data Definition Language) operation, not a DML (Data Manipulation Language) operation. This means it cannot be rolled back in MySQL.
-- Start a new transaction
START TRANSACTION;

-- Perform TRUNCATE operation (remove all rows from the table)
TRUNCATE TABLE employees;

-- Check the data after TRUNCATE (before commit or rollback)
SELECT * FROM employees;

-- Rollback will not work here, because TRUNCATE cannot be rolled back in MySQL.
-- Try ROLLBACK (it won't undo TRUNCATE in MySQL)
ROLLBACK;

-- Check the data again (it won't restore the data)
SELECT * FROM employees;

Expected Outcome: After TRUNCATE, the table will be empty, and ROLLBACK will have no effect because TRUNCATE in MySQL cannot be rolled back.
If you had used COMMIT, the data would be permanently deleted.
-- COMMIT the changes if you want the TRUNCATE to be permanent
COMMIT;

-- Check the data after commit
SELECT * FROM employees;

Expected Outcome: The table will remain empty after a successful commit of the TRUNCATE.
Step 4: Use DROP (Not Rollbackable in MySQL)
In MySQL, DROP is also a DDL command and cannot be rolled back once executed. It will completely remove the table from the database.
-- Start a new transaction
START TRANSACTION;

-- Perform DROP operation (remove the employees table)
DROP TABLE employees;

-- Check if the table still exists (before commit or rollback)
SELECT * FROM employees; -- This will give an error because the table no longer exists

-- Rollback will not work here, because DROP cannot be rolled back in MySQL.
ROLLBACK;

-- Try checking the data again (it won't restore the table)
SELECT * FROM employees; -- This will give an error again

Expected Outcome: After DROP, the table is removed from the database, and ROLLBACK will not restore the table, because DROP is not rollbackable in MySQL.
If you had used COMMIT, the table would be permanently removed.
-- COMMIT the changes if you want the DROP to be permanent
COMMIT;

-- Attempting to check the table will result in an error, as it no longer exists.
SELECT * FROM employees; -- Error: Table doesn't exist

Summary:
DELETE: Can be rolled back within a transaction.
TRUNCATE: Cannot be rolled back in MySQL (it’s treated as a DDL command).
DROP: Cannot be rolled back in MySQL (it’s a DDL command that completely removes the table).
To safely perform actions that can be rolled back in MySQL, you should rely on DELETE within transactions. TRUNCATE and DROP are permanent changes in MySQL and cannot be undone unless you have backups or restore points.
